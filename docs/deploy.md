# Как поднять Корсика на сервере

Здесь написано, как перенести бота с Mac на сервер и открыть кабинет по адресу `korsik.udav.team`. Само подключение домена и вебхука ещё не делали: это инструкция на потом. Перед началом прочитайте раздел «Что где сейчас».

## Что где сейчас

- Бот - Docker на сервере 192.168.1.60 в локальной сети: папка `/opt/docker/korsik`, сеть `learnio_news_proxy_net`, кабинет на `127.0.0.1:8095` сервера. События МАКС он получает сам, long polling, домен ему не нужен.
- Модель - отдельный компьютер с Windows (RTX 4070 Super, `qwen3:14b` и `bge-m3`). Компьютер стоит в той же локальной сети, что и сервер. Модель включает кнопка в окне «Корсик модель», бот ходит к ней по адресу `OLLAMA_URL`. Порт модели 11434 на Windows открыт только для сервера 192.168.1.60, с этого адреса и приходят запросы бота из Docker. Выключена - бот работает в упрощённом режиме. Как поставить и включить, написано в [deploy/windows/README.md](../deploy/windows/README.md).
- Домен `korsik.udav.team` создан, но его A-запись указывает на 5.101.152.78 (это Beget). Нужен сервер 37.204.116.197, где уже работает keys.udav.team за Nginx Proxy Manager (дальше NPM).

Цель такая:

```
МАКС  <---- бот сам забирает события ----  Docker на сервере 192.168.1.60
                                              |  |
браузер HR --> korsik.udav.team --> NPM ------'  '-- локальная сеть --> Windows с Ollama
              (HTTPS, Let's Encrypt)
```

## 1. Остановить бота на Mac

Один токен МАКС, один получатель событий. Если на Mac и на сервере работает по боту, они будут отнимать друг у друга сообщения, и часть из них потеряется. Сначала остановите процесс на Mac, потом запускайте на сервере.

## 2. Доступ к модели по локальной сети

Отдельно на сервере ничего ставить не нужно: сервер и компьютер с моделью в одной сети. На Windows установка из [deploy/windows/README.md](../deploy/windows/README.md) открывает порт 11434 только для 192.168.1.60, для остальных устройств сети он закрыт. Адрес компьютера с моделью показывает окно «Корсик модель» и печатает `check-ollama.ps1`. Включите модель в окне и проверьте с сервера:

```
curl -m 5 http://<адрес Windows>:11434/api/version
```

Должна прийти версия Ollama. Если пусто: модель выключена, у компьютера сменился адрес или у сервера другой адрес, чем разрешён на Windows. Последние разделы инструкции для Windows про это.

## 3. DNS: направить korsik.udav.team на сервер

Сертификат Let's Encrypt проверяет адрес по DNS, поэтому запись нужно поменять до выпуска сертификата, иначе проверка попадёт на чужой сервер и не пройдёт.

1. Откройте панель, где управляется DNS зоны `udav.team`. Запись сейчас указывает на адрес Beget, значит, она заведена там или поддомен числится в хостинге Beget. Посмотрите, где и как заведён `keys.udav.team`, и сделайте так же.
2. Найдите запись типа A с именем `korsik` (полное имя `korsik.udav.team`).
3. Значение 5.101.152.78 замените на 37.204.116.197. TTL поставьте 300 секунд, на время настройки так быстрее.
4. Если для `korsik` есть запись AAAA (IPv6) или CNAME, удалите её. Иначе часть посетителей будет попадать на старый адрес.
5. Проверьте с любого компьютера:

   ```
   dig +short korsik.udav.team
   ```

   Должно вернуться `37.204.116.197`. Если там ещё старый адрес, подождите TTL и спросите снова. На Windows вместо `dig` команда `nslookup korsik.udav.team 1.1.1.1`.

## 4. Бот в Docker

На сервере нужны Docker и плагин compose (если keys.udav.team работает в Docker, они уже стоят):

```
git clone <адрес репозитория> korsik-bot
cd korsik-bot
cp .env.example .env
nano .env
mkdir -p data
sudo chown -R 1000:1000 data scenario
```

Внутри контейнера бот работает под пользователем с номером 1000. Если вы на сервере тоже под ним, `chown` ничего не изменит. Папка `scenario/` подключена в контейнер: когда HR загружает новый сценарий в кабинете, файл заменяется прямо в ней. Не забудьте потом скачать его из кабинета и положить в git, иначе при обновлении кода сценарий вернётся к старому.

В `.env` заполните:

| Переменная | Что вписать |
|---|---|
| `MAX_BOT_TOKEN` | токен бота из кабинета МАКС |
| `BOT_USERNAME` | можно пусто, бот сам спросит у МАКС |
| `ADMIN_PASSWORD` | длинный пароль для кабинета, он потом будет виден из интернета |
| `SECRET_KEY` | случайная строка, `openssl rand -hex 32` |
| `OLLAMA_URL` | `http://<адрес компьютера с моделью в локальной сети>:11434` |
| `LLM_MODEL` | `qwen3:14b`, как в окне на Windows (в `.env.example` стоит `qwen3:8b`) |
| `EMBED_MODEL` | `bge-m3` |
| `DEMO_MODE` | `1` до защиты, потом `0` |
| `HR_CHAT_ID` | пусто или номер группового чата HR |

`WEB_HOST` и `WEB_PORT` в `.env` для Docker не нужны, их задаёт `compose.yaml`. Запуск:

```
docker compose up -d --build
docker compose logs -f korsik
curl http://127.0.0.1:8080/health
```

Последняя команда должна вернуть `{"ok":true}`. Порт 8080 открыт только на 127.0.0.1 сервера, из интернета по нему не достучаться.

Проверка, что контейнер видит модель (модель включена):

```
docker compose run --rm --no-deps korsik python -c "import httpx; print(httpx.get('http://<адрес Windows>:11434/api/version', timeout=5).text)"
```

Запросы из контейнера уходят в локальную сеть с адреса сервера 192.168.1.60, поэтому брандмауэр на Windows их пропускает. Если с сервера `curl` проходит, а из контейнера нет, сравните адрес в `OLLAMA_URL` с тем, что показывает окно на Windows.

Документы. Папку `data/kb/` с файлами компании на сервер нужно перенести руками (в git их нет), потом:

```
docker compose exec korsik python -m tools.load_kb kb-demo --demo
docker compose exec korsik python -m tools.load_kb data/kb/файл.pdf --tags "GTP"
```

Первая строка загружает демо-файлы столовых. Вторая показывает, как грузить документ с тегами. Ту же загрузку можно сделать в кабинете, раздел «База знаний». Скан ПВТР лучше загрузить уже распознанным текстом (`data/kb/...txt`), распознавание в контейнере медленное. Не копируйте `data/korsik.db` с Mac: там тестовые новички и токены загруженных картинок.

## 5. Прокси в Nginx Proxy Manager

Как запущен NPM на сервере, мы не видели. Это определяет адрес, на который он пойдёт. Выясните командой:

```
docker ps --format '{{.Names}}  {{.Ports}}' | grep -i -E 'proxy|nginx'
```

Если NPM работает в Docker (скорее всего), `127.0.0.1` внутри него - это сам NPM, и порт бота он там не увидит. Подключите бота к сети NPM. Имя сети:

```
docker inspect <имя контейнера NPM> --format '{{range $name, $v := .NetworkSettings.Networks}}{{$name}} {{end}}'
```

Создайте на сервере рядом с `compose.yaml` файл `compose.override.yaml` (в git не коммитить) и подставьте имя сети:

```yaml
services:
  korsik:
    networks: [proxy]
networks:
  proxy:
    external: true
    name: <имя сети NPM>
```

Потом `docker compose up -d`. В NPM адрес для бота будет `korsik-bot`, порт 8080. Если NPM стоит прямо на сервере или работает с сетью хоста, адрес `127.0.0.1`, порт 8080, и override не нужен.

Дальше в панели NPM:

1. Hosts - Proxy Hosts - Add Proxy Host.
2. Domain Names: `korsik.udav.team`.
3. Scheme: `http`. Forward Hostname / IP: `korsik-bot` (или `127.0.0.1`). Forward Port: `8080`.
4. Включить Block Common Exploits. Websockets не нужны, в кабинете нет скриптов.
5. Вкладка SSL: SSL Certificate - Request a new SSL Certificate, включить Force SSL и HTTP/2, указать почту, согласиться с условиями Let's Encrypt. Порт 80 сервера должен быть доступен из интернета, как и для keys.udav.team.
6. Save.

Если загрузка документа в кабинете падает с ошибкой 413, на вкладке Advanced добавьте `client_max_body_size 25m;`: кабинет принимает файлы до 20 МБ.

## 6. Проверка

- https://korsik.udav.team открывается с замком, показывает страницу входа.
- Вход по `ADMIN_PASSWORD`, на главной написано «Модель работает», если окно на Windows включено.
- Добавьте рекрутера, откройте его ссылку в МАКС, потом заведите новичка и откройте его ссылку другим аккаунтом. Придёт приветствие и вопрос «ты или вы».
- Задайте вопрос по документу и вопрос, которого в документах нет. Второй должен дойти до рекрутера.

## Что будет, когда модель выключена

Компьютер с Windows спит, окно закрыто, компьютер выпал из сети: бот не падает. В течение минуты он замечает недоступность и переходит в упрощённый режим. Рекрутерам и чату HR приходит одно сообщение об этом, на главной странице кабинета видно режим. Сценарий, кнопки и опросы идут как обычно, на вопросы бот отвечает цитатой из документа с подписью или передаёт их рекрутеру. Включили модель - через минуту всё возвращается само. Куски документов без векторов бот досчитывает при каждой проверке модели, пока она доступна; после неудачной попытки ждёт пять минут.

Если остановлен сам бот (сервер выключен, контейнер упал), он молчит. После запуска планировщик отправит все шаги, время которых прошло, пока бот стоял, даже если они опоздали на несколько дней. Пропускаются только шаги, которые опоздали больше чем на сутки уже к моменту, когда новичок открыл свою ссылку. Контейнер стоит с `restart: unless-stopped`, после перезагрузки сервера поднимется сам.

## Вебхук позже

Сейчас вебхука нет: бот сам забирает события, поэтому домен нужен только для кабинета. Вебхук (МАКС сам присылает события на `https://korsik.udav.team/...`) потребует: добавить в `app/web.py` маршрут, который принимает событие и передаёт его в `bot.dispatch`; проверять секрет подписки, как написано в документации МАКС; подписать бота запросом `POST /subscriptions`; отключить `bot.polling_loop` в `main.py`. Два способа одновременно не включать, выбираем один.

## Обновление и копия

Обновить код: `git pull && docker compose up -d --build`. Данные лежат в `data/` и в пересборке не теряются.

Резервная копия базы, пока бот работает:

```
docker compose exec korsik python -c "import sqlite3; s = sqlite3.connect('data/korsik.db'); d = sqlite3.connect('data/backup.db'); s.backup(d)"
```

Файл `data/backup.db` потом скопируйте в безопасное место. Загруженные файлы лежат в `data/uploads/`, `data/kb/` и `data/images/`.

Откатиться на прошлую версию: `git checkout <коммит> && docker compose up -d --build`.

## Если что-то не так

- Сертификат не выпускается: `dig +short korsik.udav.team` не показывает 37.204.116.197 или порт 80 закрыт.
- 502 Bad Gateway: бот не запущен (`docker compose ps`) или NPM не видит его по этому адресу (см. раздел 5).
- В кабинете не работает вход после перезапуска: пустой `SECRET_KEY`, сессии ломаются при каждом старте.
- Бот молчит в МАКС: токен не тот, или на Mac остался второй процесс. Смотрите `docker compose logs korsik`.
- Запись в `data/` не получается: права на папку, см. `chown` в разделе 4.
